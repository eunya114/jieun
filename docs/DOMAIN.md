# DOMAIN.md — 요금제 변경 서비스 (모바일 웹)

> 근거: 고객 인터뷰(도메인 전문가 답변), 유저 스토리, `docs/screens.md`, PRD 인터뷰 답변.
> 표시 규칙: **[확정]** 사용자가 확인함 · **[가정]** 확인 전 추측 · **[열린 질문]** 아직 정해지지 않음

## 0. 배경 [확정]

- **무엇을:** 요금제를 비교하고 변경하는 모바일 웹 (요금제 목록 → 상세 → 변경 신청 확인 → 완료)
- **누구를 위해:** 데이터 부족 알림을 받고 요금제를 바꾸려는 **기존 U+ 고객**
- **왜:** 고객은 데이터 외 혜택과 1GB당 금액을 판단하지 못해, 그냥 한 단계 위 요금제를 고르거나 상담원에게 전화한다. 그 결과 데이터가 남거나 원하던 혜택이 없어 후회해도, 1개월 동안은 다시 바꿀 수 없다.

## 1. 용어집

| 용어 | 정의 | 비고 |
|---|---|---|
| **요금제 변경** | 기존 고객이 지금 쓰는 요금제를 다른 요금제로 바꾸는 것 | [확정] "구독 신청", "신청"과 같은 뜻. **화면에는 "요금제 변경"으로 통일**한다. |
| 구독 신청 / 신청 | = 요금제 변경 | [확정] 화면 문구에 쓰지 않는다. screens.md의 "신청하기", "신청 완료"는 "요금제 변경"으로 바꾼다. |
| **현재 요금제** | 고객이 지금 쓰고 있는 요금제 | [확정] 목록의 3개 중 하나가 아닐 수도 있다. |
| **판매 요금제** | 이 화면에서 고를 수 있는 요금제 (기본 / 표준 / 무제한) | [확정] screens.md의 3개 그대로 쓴다. |
| **제공량** | 요금제가 매월 제공하는 데이터·통화·문자 양 | |
| **혜택** | 데이터 외에 요금제가 주는 것 | [확정] 이번 범위에서는 **통화·문자만** 해당한다. |
| **월 요금** | 요금제의 한 달 금액 | [가정] screens.md 기준 부가세 포함 금액 |
| **1GB당 금액** | 월 요금 ÷ 데이터 제공량(GB) | [확정] 10원 단위 반올림. 무제한은 "무제한"으로 표시한다. |
| **월 평균 사용량** | 최근 3개월 데이터 사용량의 평균 | [확정] 기록이 3개월보다 적으면 있는 달만 평균한다. |
| **추천** | 월 평균 사용량에 맞는 요금제에 붙는 태그 | [확정] 규칙은 4-1 참고 |
| **사용 중** | 판매 요금제 중 고객의 현재 요금제와 같은 카드에 붙는 표시 | [확정] |
| **마지막 변경일** | 고객이 요금제를 마지막으로 바꾼 날 | [확정] 변경 제한(1개월)의 기준일 |
| **변경 제한** | 마지막 변경일부터 1개월 동안 요금제를 다시 바꿀 수 없는 상태 | [확정] |
| **일할 계산** | 이번 달 요금을 예전 요금제와 새 요금제를 쓴 날짜만큼 나눠 계산하는 것 | [확정] |
| **확인 번호** | 변경 완료 후 발급되는 번호 | screens.md 예시 형식: `YYYYMMDD-NNNNNN` [가정] |

## 2. 사용자와 역할

| 역할 | 목표 | 비고 |
|---|---|---|
| **기존 U+ 고객** (유일한 사용자) | 데이터 부족 알림을 받은 뒤, 후회하지 않을 요금제를 스스로 골라 바꾸기 | [확정] 이미 로그인한 상태로 들어온다. 신규 가입 고객은 대상이 아니다. |

- 상담원, 관리자 등 다른 역할은 이번 범위에 없다. [확정: 상담원 연결 제외]

### 유저 스토리
- **US1** 데이터 부족 알림을 받은 고객은 지금 요금제가 부족한지 판단하기 위해 현재 요금제의 데이터 용량과 금액을 확인한다.
- **US2** 고객은 더 내는 돈만큼 데이터가 얼마나 늘어나는지 알기 위해 요금제별 1GB당 금액과 추가 금액을 비교한다.
- **US3** 고객은 데이터 말고도 원하는 혜택이 있는 요금제를 고르기 위해 요금제별 혜택을 확인한다.
- **US4** 고객은 1개월 동안 다시 바꿀 수 없는 요금제를 후회 없이 고르기 위해 변경 전에 바꿀 요금제와 조건을 한 번 더 확인하고 변경한다.

## 3. 핵심 흐름

### 3-1. 기본 흐름 (요금제 변경 성공)

```
[요금제 목록] ──카드 / 요금제 보기──▶ [요금제 상세] ──이 요금제로 변경──▶ [변경 신청 확인] ──변경하기──▶ (처리 중) ──성공──▶ [변경 완료]
      ▲                                   │
      └──────────── 다른 요금제 보기 ◀────┘
```

| # | 화면 | 하는 일 | 유저 스토리 |
|---|---|---|---|
| 1 | 요금제 목록 | 현재 요금제(데이터·통화·문자·월 요금)와 월 평균 사용량을 보여 준다. 판매 요금제 카드마다 1GB당 금액, 현재보다 늘거나 줄어드는 금액과 데이터, 통화·문자, 추천 / 사용 중 표시를 보여 준다. | US1, US2, US3 |
| 2 | 요금제 상세 | 선택한 요금제의 가격, 혜택(통화·문자), 조건, 현재 요금제와의 차이를 보여 주고, "변경 후 1개월 동안 다시 바꿀 수 없음"을 안내한다. | US2, US3, US4 |
| 3 | 변경 신청 확인 ⭐저장 | 현재 → 변경 요금제를 비교해 요약하고, 즉시 적용·일할 계산·1개월 제한을 안내하고, 약관 동의를 받은 뒤 변경한다. **개인정보·결제 정보는 입력받지 않는다.** | US4 |
| 4 | 변경 완료 | 완료 안내, 확인 번호, 변경 전 → 변경 후 요금제를 보여 준다. | US4 |

### 3-2. 예외 흐름

| 상황 | 처리 | 근거 |
|---|---|---|
| **변경 제한 기간인 고객** (마지막 변경일부터 1개월이 지나지 않음) | 목록과 상세는 볼 수 있다. 변경 버튼은 막고 "○월 ○일부터 변경 가능"을 안내한다. | [확정] |
| **현재 요금제와 같은 요금제** | 카드에 "사용 중"을 표시하고, 그 요금제로는 바꿀 수 없다. | [확정] |
| **현재 요금제가 목록 밖 요금제** | 맨 위 현재 요금제 영역에 보여 주고, 같은 방식(금액·데이터 차이)으로 비교한다. 목록에는 "사용 중" 카드가 없다. | [확정] |
| **더 낮은 요금제로 변경** | 허용한다. 차이는 "월 10,000원 줄어듦 · 데이터 10GB 줄어듦"처럼 보여 준다. | [확정] |
| **약관에 동의하지 않음** | 변경 버튼을 누를 수 없다. | [가정] |
| **변경 처리 중** | 3번 화면의 로딩 상태로 처리 중임을 안내한다. 따로 화면을 두지 않는다. | [확정: 4개 화면 구성] |
| **변경 실패** | 실패를 안내하고, 변경 신청 확인 화면으로 돌아가 다시 시도하게 한다. 요금제는 바뀌지 않은 상태로 남는다. | [확정] |
| **사용 기록이 3개월보다 적음** | 있는 달만 평균해서 추천한다. | [확정] |

## 4. 비즈니스 규칙과 제약

### 4-1. 추천 [확정]
- **규칙:** 판매 요금제 중 데이터 제공량이 **최근 3개월 월 평균 사용량 이상**인 요금제 가운데 **월 요금이 가장 싼 것** 1개에 "추천" 태그를 붙인다.
- 사용 기록이 3개월보다 적으면 있는 달만 평균한다.
- 무제한 요금제는 어떤 사용량보다도 크거나 같다고 본다. 그래서 평균 사용량이 15GB보다 많으면 무제한이 추천된다. [가정]
- 추천 요금제가 현재 요금제와 같을 때 "추천"과 "사용 중"을 함께 표시할지는 → [열린 질문 Q3]

### 4-2. 1GB당 금액 [확정]
- `월 요금 ÷ 데이터 제공량(GB)`을 **10원 단위로 반올림**한다.
  - 기본: 19,000 ÷ 5 = 3,800원
  - 표준: 29,000 ÷ 15 = 1,933.3… → **1,930원**
  - 무제한: **"무제한"**으로 표시하고 숫자는 보여 주지 않는다.

### 4-3. 현재 요금제와의 차이 [확정]
- 금액 차이 = 대상 요금제 월 요금 − 현재 요금제 월 요금
- 데이터 차이 = 대상 요금제 데이터 − 현재 요금제 데이터
- 값이 양수면 "늘어남", 음수면 "줄어듦"으로 표시한다. 낮은 요금제로 바꾸는 것도 허용한다.
- 한쪽이 무제한일 때 데이터 차이를 어떻게 표시할지 → [열린 질문 Q2]

### 4-4. 변경 적용과 요금 [확정]
- 변경이 완료되면 **즉시** 새 요금제가 적용된다.
- 이번 달 요금은 **일할 계산**한다.
- 일할 계산한 예상 금액을 화면에 숫자로 보여 줄지, 문구로만 안내할지 → [열린 질문 Q1]

### 4-5. 변경 제한 [확정]
- **마지막 변경일부터 1개월** 동안은 다시 바꿀 수 없다.
  - 예: 10월 20일에 바꾸면 11월 20일부터 다시 바꿀 수 있다.
- 제한 중인 고객도 목록과 상세는 볼 수 있고, 변경만 막는다.
- 1월 31일처럼 다음 달에 같은 날짜가 없는 경우 → [열린 질문 Q4]

### 4-6. 본인 확인과 입력 [확정]
- 고객은 이미 로그인한 상태다. 개인정보(이름, 연락처, 이메일)와 결제 정보(카드번호, 유효기간)는 **입력받지 않는다.**
- 변경 전에 **약관 동의**를 받는다. 이 부분은 선택지 설명에 포함된 내용으로 확정했다. 약관 문구 → [열린 질문 Q5]

## 5. 데이터 모델

```
Customer (고객) ──1:1── CurrentSubscription (현재 가입) ──N:1── Plan (요금제)
     │                          │
     │                          └── lastChangedAt (마지막 변경일)
     ├──1:N── MonthlyUsage (월별 데이터 사용량, 최근 3개월)
     └──1:N── PlanChange (요금제 변경 내역) ──N:1── Plan (변경 전 / 변경 후)
```

### Plan (요금제)
| 필드 | 타입 | 설명 |
|---|---|---|
| id | string | |
| name | string | 기본 / 표준 / 무제한, 또는 목록 밖 요금제 이름 |
| dataGB | number \| `unlimited` | 데이터 제공량 |
| voice | number(분) \| `unlimited` | 통화 제공량 |
| sms | string | 문자 제공 (예: 기본 제공) |
| monthlyFee | number(원) | 월 요금, 부가세 포함 [가정] |
| isOnSale | boolean | 이 화면에서 고를 수 있는 판매 요금제인지 |

**판매 요금제 (예시 데이터, screens.md 기준) [확정]**

| 이름 | 데이터 | 통화 | 문자 | 월 요금 | 1GB당 금액 |
|---|---|---|---|---|---|
| 기본 | 5GB | 100분 | [열린 질문 Q6] | 19,000원 | 3,800원 |
| 표준 | 15GB | 무제한 | 기본 제공 | 29,000원 | 1,930원 |
| 무제한 | 무제한 | 무제한 | [열린 질문 Q6] | 49,000원 | 무제한 |

### CurrentSubscription (현재 가입)
| 필드 | 설명 |
|---|---|
| planId | 현재 요금제 (판매 요금제가 아닐 수 있음) |
| lastChangedAt | 마지막 변경일. 변경 제한 계산에 쓴다. |

### MonthlyUsage (월별 사용량)
| 필드 | 설명 |
|---|---|
| month | YYYY-MM |
| dataUsedGB | 그 달에 쓴 데이터 |

→ **월 평균 사용량** = 최근 3개월(없으면 있는 달) `dataUsedGB` 평균

### PlanChange (요금제 변경)
| 필드 | 설명 |
|---|---|
| confirmationNo | 확인 번호 |
| fromPlanId / toPlanId | 변경 전 / 변경 후 요금제 |
| requestedAt | 변경 일시. 이 값이 새 lastChangedAt이 된다. |
| status | 처리 중 / 성공 / 실패 |
| termsAgreed | 약관 동의 여부 |

### 계산값 (저장하지 않음)
- `pricePerGB`, `feeDiff`, `dataDiff`, `isRecommended`, `isCurrent`, `canChange`, `changeAvailableFrom`(= lastChangedAt + 1개월)

## 6. 이번 범위에서 하지 않을 것 [확정]

- 데이터 추가 구매
- 상담원 연결 (전화, 채팅)
- 실제 서버 연동 (고객 정보와 요금제 변경 API). 화면은 **예시 데이터**로 동작한다.
- 로그인과 본인 인증 (이미 로그인한 상태라고 본다)
- 신규 가입 고객
- 데이터 외 혜택 중 통화·문자가 아닌 것 (멤버십, 부가서비스 등)
