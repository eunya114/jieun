# PRD — 요금제 변경 (모바일 웹)

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 (v0.1) |
| 근거 문서 | `DOMAIN.md` (용어, 규칙, 데이터의 기준) |
| 참고 자료 | `docs/screens.md`, `links.md` (Figma 화면 링크, Make 링크) |
| 기준 우선순위 | **PRD.md** > screens.md > 화면 링크 > Make 링크 > flow.png |

> 이 PRD는 `DOMAIN.md`의 확정 내용만 요구사항으로 씁니다.
> - **[가정]** 아직 확인받지 못한 추측입니다.
> - **[열린 질문]** 아직 정해지지 않았습니다. 구현할 때는 이 문서의 **임시 처리**를 따르고, 답이 나오면 바꿉니다.

## 1. 개요

### 1-1. 한 줄 요약
데이터 부족 알림을 받은 기존 U+ 고객이 **1GB당 금액과 혜택을 비교해 맞는 요금제를 직접 고르고, 그 자리에서 바꿀 수 있는** 모바일 웹입니다.

### 1-2. 문제
고객 인터뷰에서 확인한 흐름입니다.

1. 데이터 부족 알림 문자를 받고 요금제를 바꿔야겠다고 생각한다.
2. 앱에서 현재 요금제의 데이터 용량과 금액을 확인하고, 다른 요금제와 비교한다.
3. **막히는 지점:** 데이터 외에 어떤 혜택이 있는지 모르고, 더 내는 돈에 비해 데이터가 얼마나 늘어나는지(1GB당 금액) 계산하지 못한다.
4. 결국 **그냥 한 단계 위 요금제로 바꾸거나 상담원에게 전화**한다.
5. 바꾼 뒤 **데이터가 남거나 원하던 혜택이 없어 후회**하지만, **1개월 동안은 다시 바꿀 수 없다.**

### 1-3. 목표
| # | 목표 | 관련 유저 스토리 |
|---|---|---|
| G1 | 고객이 현재 요금제와 사용량을 보고, 지금 요금제가 맞는지 판단할 수 있다. | US1 |
| G2 | 고객이 요금제별 1GB당 금액과 현재 요금제와의 금액·데이터 차이를 계산 없이 비교할 수 있다. | US2 |
| G3 | 고객이 요금제별 혜택(통화·문자)을 확인하고 고를 수 있다. | US3 |
| G4 | 고객이 1개월 변경 제한을 알고, 변경 전에 내용을 다시 확인한 뒤 바꿀 수 있다. | US4 |

### 1-4. 성공 지표
- [열린 질문 Q10] 성공을 무엇으로 잴지(예: 변경 후 1개월 안 재변경 문의 수, 상담원 문의 전환율) 정해지지 않았습니다. 수치 목표는 정해지면 적습니다.

## 2. 사용자

| 역할 | 설명 | 목표 |
|---|---|---|
| **기존 U+ 고객** | 이미 가입했고, 로그인한 상태로 들어오는 고객 (유일한 사용자) | 후회하지 않을 요금제를 스스로 골라 바꾸기 |

### 유저 스토리
- **US1** 데이터 부족 알림을 받은 고객은 지금 요금제가 부족한지 판단하기 위해 현재 요금제의 데이터 용량과 금액을 확인한다.
- **US2** 고객은 더 내는 돈만큼 데이터가 얼마나 늘어나는지 알기 위해 요금제별 1GB당 금액과 추가 금액을 비교한다.
- **US3** 고객은 데이터 말고도 원하는 혜택이 있는 요금제를 고르기 위해 요금제별 혜택을 확인한다.
- **US4** 고객은 1개월 동안 다시 바꿀 수 없는 요금제를 후회 없이 고르기 위해 변경 전에 바꿀 요금제와 조건을 한 번 더 확인하고 변경한다.

## 3. 범위

### 3-1. 이번에 하는 것
- 화면 4개: **요금제 목록 → 요금제 상세 → 변경 신청 확인 → 변경 완료**
- 추천, 1GB당 금액, 현재 요금제와의 차이 계산
- 변경 제한(1개월), 사용 중 요금제, 변경 실패 같은 예외 처리
- **예시 데이터(mock)**로 동작 (서버 없음)

### 3-2. 이번에 하지 않는 것
- 데이터 추가 구매
- 상담원 연결 (전화, 채팅)
- 실제 서버 연동 (고객 정보, 요금제 변경 API)
- 로그인, 본인 인증 (이미 로그인한 상태라고 봅니다)
- 신규 가입 고객
- 통화·문자가 아닌 혜택 (멤버십, 부가서비스 등)

### 3-3. screens.md와 다른 점
`docs/screens.md`는 참고용 흐름입니다. 이 PRD가 우선합니다.

| screens.md | 이 PRD | 이유 |
|---|---|---|
| 화면 제목 "요금제 추천" | **"요금제 목록"** | 추천은 카드 1개에만 붙는 태그이고, 화면은 전체 요금제를 보여 줍니다. [가정] |
| 신청 폼 (이름·연락처·이메일·카드번호·유효기간 입력) | **변경 신청 확인** (입력 없음, 약관 동의만) | 기존 고객이 로그인한 상태로 쓰기 때문입니다. |
| "신청", "신청하기", "신청 완료" | **"요금제 변경"**으로 통일 | DOMAIN.md 용어 규칙 |
| 입력 오류 / 처리 중 / 실패 안내를 각각 별도 화면으로 둠 | 변경 신청 확인 화면의 **상태**로 합침 | 화면을 4개로 유지하기 위해서 (입력 항목이 없으니 입력 오류 화면도 필요 없음) |
| 현재 요금제 정보 없음 | 목록 맨 위에 **현재 요금제와 월 평균 사용량** 표시 | US1 |
| 카드에 1GB당 금액과 차이 정보 없음 | **1GB당 금액, 금액·데이터 차이** 표시 | US2 |

## 4. 화면별 요구사항

공통
- 모바일 웹, 기준 너비 **390px** (Figma 화면 기준)
- 모든 화면에 Header(제목, 뒤로가기 `icon/arrowLeft`)가 있습니다.
- 컴포넌트, 토큰, 화면 구성은 **Figma 화면 링크**를 따릅니다. Make 링크는 화면 이동 흐름만 참고합니다. (`links.md`)
- 금액은 천 단위 쉼표와 "원"을 붙여 씁니다. (예: 29,000원)

### 4-1. 요금제 목록 (US1, US2, US3)

**목적:** 현재 요금제와 판매 요금제를 한눈에 비교하고, 상세를 볼 요금제를 고른다.

| ID | 요구사항 |
|---|---|
| L-1 | 맨 위에 **현재 요금제** 영역을 둡니다: 요금제 이름, 데이터, 통화, 문자, 월 요금 |
| L-2 | 현재 요금제 영역에 **월 평균 사용량**(최근 3개월)을 보여 줍니다. [열린 질문 Q7 → 임시 처리: "최근 3개월 평균 ○GB 사용"으로 보여 줍니다] |
| L-3 | 판매 요금제 3개(기본, 표준, 무제한)를 카드로 보여 줍니다. |
| L-4 | 카드마다 보여 줄 것: 이름, 데이터, 통화, 문자, 월 요금, **1GB당 금액**, **현재 요금제와의 금액 차이**, **데이터 차이** |
| L-5 | 추천 규칙(5-1)에 맞는 카드 1개에 **"추천"** 태그를 붙입니다. |
| L-6 | 현재 요금제와 같은 카드에는 **"사용 중"**을 표시합니다. 이 카드로도 상세에는 갈 수 있지만, 상세에서 변경할 수는 없습니다. |
| L-7 | 카드 또는 "요금제 보기" 버튼을 누르면 → 요금제 상세로 갑니다. |
| L-8 | 고객이 **변경 제한 기간**이면, 목록 위쪽에 "○월 ○일부터 요금제를 변경할 수 있어요"를 안내합니다. 목록과 상세는 그대로 볼 수 있습니다. |
| L-9 | 하단에 "모든 요금은 부가세 포함 금액입니다."를 안내합니다. [가정: 부가세 포함] |

**인수 조건**
- 현재 요금제가 표준(29,000원, 15GB)이면, 기본 카드는 "월 10,000원 줄어듦 · 데이터 10GB 줄어듦"을 보여 준다.
- 표준 카드의 1GB당 금액은 **1,930원**, 기본 카드는 **3,800원**, 무제한 카드는 **"무제한"**이다.
- 현재 요금제가 목록 밖 요금제면, 어떤 카드에도 "사용 중"이 없다. 대신 현재 요금제 영역에 그 요금제가 보인다.

### 4-2. 요금제 상세 (US2, US3, US4)

**목적:** 선택한 요금제의 가격, 혜택, 조건을 확인하고 변경할지 정한다.

| ID | 요구사항 |
|---|---|
| D-1 | 요금제 이름, 월 요금, 데이터, 통화, 문자, 1GB당 금액, 추천 / 사용 중 표시를 보여 줍니다. |
| D-2 | **현재 요금제와 비교**를 보여 줍니다: 현재 → 이 요금제의 월 요금과 데이터, 그리고 그 차이 |
| D-3 | 조건 안내: 부가세 포함 [가정], 변경 즉시 적용, 이번 달 요금은 일할 계산 |
| D-4 | 변경 제한 안내: **"변경 후 1개월 동안은 다시 바꿀 수 없어요."** |
| D-5 | 버튼 "이 요금제로 변경" (Primary) → 변경 신청 확인으로 갑니다. |
| D-6 | 버튼 "다른 요금제 보기" (Secondary) → 요금제 목록으로 돌아갑니다. |
| D-7 | **사용 중 요금제**의 상세에서는 변경 버튼을 막고 "지금 사용 중인 요금제예요"를 표시합니다. |
| D-8 | 고객이 **변경 제한 기간**이면 변경 버튼을 막고 "○월 ○일부터 변경할 수 있어요"를 표시합니다. |

### 4-3. 변경 신청 확인 ⭐저장 (US4)

**목적:** 바꿀 내용을 마지막으로 확인하고 요금제를 변경한다.

| ID | 요구사항 |
|---|---|
| C-1 | **변경 요약**을 보여 줍니다: 현재 요금제 → 변경할 요금제 (이름, 월 요금, 데이터, 통화, 문자), 금액·데이터 차이 |
| C-2 | 적용 안내: "변경하면 바로 새 요금제가 적용돼요." / "이번 달 요금은 일할 계산돼요." [열린 질문 Q1 → 임시 처리: 금액은 보여 주지 않고 문구로만 안내합니다] |
| C-3 | 제한 안내: "변경 후 1개월 동안(○월 ○일까지)은 다시 바꿀 수 없어요." 날짜는 변경일 + 1개월로 계산합니다. |
| C-4 | **개인정보와 결제 정보 입력란은 두지 않습니다.** |
| C-5 | 약관 동의 체크박스: "[필수] 서비스 이용 약관에 동의합니다." [열린 질문 Q5] |
| C-6 | 버튼 "요금제 변경" (Primary): 약관에 동의하기 전에는 누를 수 없습니다. [가정] |
| C-7 | 버튼 "취소" (Secondary) → 요금제 상세로 돌아갑니다. |
| C-8 | "요금제 변경"을 누르면 → **처리 중** 상태가 됩니다 (버튼 막힘, "요금제를 변경하고 있어요" 표시, 같은 요청 중복 방지). |
| C-9 | 처리에 성공하면 → 변경 완료로 갑니다. |
| C-10 | 처리에 실패하면 → **실패** 상태가 됩니다: "요금제를 변경하지 못했어요. 다시 시도해 주세요." 요금제는 바뀌지 않고, 고객은 같은 화면에서 다시 시도할 수 있습니다. |

### 4-4. 변경 완료 (US4)

**목적:** 변경이 끝났음을 알리고 결과를 보여 준다.

| ID | 요구사항 |
|---|---|
| F-1 | 완료 안내: "요금제 변경이 완료됐어요" |
| F-2 | 확인 번호를 보여 줍니다 (형식 `YYYYMMDD-NNNNNN`) [가정] |
| F-3 | 변경 내역: 변경 전 요금제 → 변경 후 요금제, 월 요금, 적용 시점("지금부터 적용"), 다음 변경 가능일 |
| F-4 | 버튼 "홈으로 이동" (Primary) [열린 질문 Q9 → 임시 처리: 요금제 목록으로 돌아갑니다. 목록에는 새 요금제가 "사용 중"으로, 변경 제한 안내와 함께 보입니다] |

## 5. 비즈니스 규칙

| ID | 규칙 | 상세 |
|---|---|---|
| **R-1 추천** | 판매 요금제 중 데이터 제공량이 **월 평균 사용량 이상**인 것 가운데 **월 요금이 가장 싼 1개** | 무제한은 어떤 사용량보다도 크거나 같다고 봅니다 [가정]. 추천이 사용 중 요금제와 같을 때 [열린 질문 Q3 → 임시 처리: 두 표시를 함께 붙입니다] |
| **R-2 월 평균 사용량** | 최근 3개월 데이터 사용량의 평균 | 기록이 3개월보다 적으면 있는 달만 평균합니다. 기록이 하나도 없으면 [열린 질문 Q8 → 임시 처리: 추천을 붙이지 않습니다] |
| **R-3 1GB당 금액** | `월 요금 ÷ 데이터(GB)`, **10원 단위 반올림** | 무제한은 "무제한"으로 표시합니다. |
| **R-4 차이 계산** | 금액 차이 = 대상 월 요금 − 현재 월 요금<br>데이터 차이 = 대상 데이터 − 현재 데이터 | 양수면 "늘어남", 음수면 "줄어듦", 0이면 "같음"으로 씁니다. 한쪽이 무제한일 때 [열린 질문 Q2 → 임시 처리: "무제한으로 늘어남" / "무제한에서 ○GB로 줄어듦"] |
| **R-5 낮은 요금제** | 더 싼 요금제로 바꾸는 것도 허용합니다. | |
| **R-6 즉시 적용** | 변경이 완료되면 바로 새 요금제가 적용됩니다. | |
| **R-7 일할 계산** | 이번 달 요금은 예전 요금제와 새 요금제를 쓴 날짜만큼 나눠 계산합니다. | 화면에는 안내 문구만 둡니다 (임시 처리, Q1). |
| **R-8 변경 제한** | **마지막 변경일부터 1개월** 동안은 다시 바꿀 수 없습니다. | 예: 10월 20일에 바꾸면 11월 20일부터 가능합니다. 다음 달에 같은 날짜가 없을 때 [열린 질문 Q4 → 임시 처리: 그 달의 마지막 날부터 가능] |
| **R-9 제한 중 접근** | 변경 제한 중에도 목록과 상세는 볼 수 있고, 변경 버튼만 막습니다. | |
| **R-10 같은 요금제** | 사용 중인 요금제로는 바꿀 수 없습니다. | |
| **R-11 입력 없음** | 개인정보와 결제 정보를 입력받지 않습니다. 약관 동의만 받습니다. | |

## 7. 화면 이동

```
[요금제 목록] ──카드 / 요금제 보기──▶ [요금제 상세] ──이 요금제로 변경──▶ [변경 신청 확인] ──요금제 변경──▶ (처리 중)
      ▲                                │  ▲                                  │                                │
      │                                │  └────────────── 취소 ──────────────┘                     성공 ↓ / 실패 → 같은 화면에서 다시 시도
      └──────── 다른 요금제 보기 ───────┘                                                          [변경 완료]
      ▲                                                                                                │
      └──────────────────────────────────── 홈으로 이동 (임시 처리, Q9) ───────────────────────────────┘
```
- 뒤로가기(Header)는 바로 전 화면으로 갑니다. 단, **변경 완료 화면에서 뒤로가기를 누르면 변경 신청 확인 화면으로 가지 않고 요금제 목록으로 갑니다.** 이미 끝난 변경을 다시 보내지 않기 위해서입니다. [가정]

## 9. 열린 질문

구현할 때는 **임시 처리**를 따르고, 답이 나오면 이 문서와 `DOMAIN.md`를 함께 고칩니다.

| # | 질문 | 임시 처리 |
|---|---|---|
| Q1 | 일할 계산한 이번 달 예상 요금을 숫자로 보여 줄지 | 문구로만 안내 |
| Q2 | 무제한이 끼었을 때 데이터 차이 표시 | "무제한으로 늘어남" / "무제한에서 ○GB로 줄어듦" |
| Q3 | 추천과 사용 중이 같은 카드일 때 | 두 표시를 함께 붙임 |
| Q4 | 다음 달에 같은 날짜가 없을 때 변경 가능일 | 그 달의 마지막 날 |
| Q5 | 약관 항목과 문구 | "[필수] 서비스 이용 약관에 동의합니다." 하나 |
| Q6 | 기본·무제한 요금제의 문자 제공량 | 기본 제공 |
| Q7 | 월 평균 사용량을 화면에 보여 줄지 | 보여 줌 |
| Q8 | 사용 기록이 하나도 없을 때 추천 | 추천 없음 |
| Q9 | "홈으로 이동"의 목적지 | 요금제 목록 |
| Q10 | 성공 지표 | 정해지면 추가 |

### 확인이 필요한 가정
- 월 요금은 부가세 포함 금액이다.
- 약관에 동의하기 전에는 변경 버튼을 누를 수 없다.
- 무제한은 어떤 사용량보다도 크거나 같다고 본다 (그래서 평균 사용량이 15GB보다 많으면 무제한이 추천된다).
- 확인 번호 형식은 `YYYYMMDD-NNNNNN`이다.
- 첫 화면 제목은 "요금제 추천" 대신 "요금제 목록"으로 한다.
- 변경 완료 화면에서 뒤로가기를 누르면 요금제 목록으로 간다.
- 막힌 버튼은 막힌 이유를 글로 함께 보여 준다.
